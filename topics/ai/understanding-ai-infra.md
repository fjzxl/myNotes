# 深入理解 AI Infra：量化分析与系统设计

> 开源免费书，Apache-2.0，**本地 PDF**：[understanding-ai-infra-zh-cn.pdf](understanding-ai-infra-zh-cn.pdf)（536 页，build-20261001 构建）
> 仓库：<https://github.com/bojieli/ai-infra-book>（6.7k star / 0.5k fork；2026-08 开源，书稿为持续修订的**初稿**）
> 在线阅读：<https://bojieli.github.io/ai-infra-book/> ｜ 作者：李博杰（GitHub: bojieli）

**核心方法论：从约束推导设计**——先明确任务与质量要求，列出计算、存储、通信和依赖，对照硬件的容量、带宽和算力做数量级估算，再看实测离物理上限还有多远。全书反复追问**数据搬移五问：搬什么、搬多少、搬几次、经过哪里、谁必须等它**。

作者的判断是编程抽象的上移：**模型成了 LLM 时代的操作系统，AI Infra 成了 LLM 时代的计算机体系结构**——本书想占的正是这个领域里《计算机体系结构：量化研究方法》（Hennessy & Patterson）的位置。姊妹篇：[深入理解 AI Agent](understanding-ai-agent.md)（那本讲大脑怎么组织，本书讲大脑跑在什么上）。

## 一、为什么收进本库

本库 AI 线目前是「理论（UML 书单）/ 工程（AI Engineering）/ 实操（Agent 109 实验）」三线：工程书讲「怎么用 vLLM / LitServe 部署」，Agent 书讲「应用怎么设计」。**缺的是应用之下的那一层：模型为什么慢、成本从哪来、硬件约束如何反过来决定系统与模型设计**——这本书正好补这一层。

前置要求：调用过模型 API 或本机跑过模型，懂一些 Python、线性代数和计算机系统基础。线性代数与考研数学一线重合，入门门槛比 UML 低；配套静态计算工具不需要 GPU 和模型权重。

## 二、书里有什么

12 章，配套 113 个实验（其中 110 个对应书内章节）与一套纯 Python 标准库的计算工具：

| 章 | 主题 | 主要问题（README 原文） | 实验 |
|---|---|---|---|
| 1 | 🏁 初识 AI Infra | 一次生成需要多少显存、计算和数据读写？ | 8 |
| 2 | 🧩 模型架构 | 注意力、历史状态与专家结构如何改变系统需求？ | 9 |
| 3 | 📊 推理与训练负载 | 任务阶段、到达模式和状态寿命如何影响资源需求？ | 10 |
| 4 | 🔥 加速器架构 | 如何在计算、存储、带宽、功耗与成本之间取舍？ | 7 |
| 5 | ⚙️ 算子与运行时 | 融合、复用、并发和调度如何减少执行开销？ | 9 |
| 6 | 🔗 超节点 | 多设备协作如何平衡容量、吞吐和同步代价？ | 10 |
| 7 | 🌐 数据中心网络 | 网络带宽、通信方式和拥塞如何影响计算效率？ | 10 |
| 8 | ⚡ 推理优化 | 批处理、KV 管理、卸载与推测解码何时有效？ | 9 |
| 9 | 🖥️ 分布式推理 | 如何放置计算和状态，并处理扩缩容与恢复？ | 10 |
| 10 | 🏋️ 训练系统 | 如何安排显存、通信和重算，让训练更高效？ | 10 |
| 11 | 📦 资源调度与运行环境 | 模型服务和工具环境如何共享资源，减少等待？ | 10 |
| 12 | 📱 端边云协同 | 任务放在本地、边缘还是云端，如何兼顾效果、延迟和成本？ | 8 |

结构上分三块：**Ch1–3 模型与负载**（软件侧需求）→ **Ch4–7 硬件与互连**（加速器、算子、超节点、网络）→ **Ch8–12 系统与部署**（推理优化、分布式、训练、调度、端边云）。

> **版本提示**：书稿是初稿、持续修订中（首版 v1.0 于 2026-09 中旬，本地这份是 2026-10-01 构建的最新 Release）。仓库滚动重新构建，章节编号可能变动，引用时以在线版核对。

**配套计算工具**（与 Agent 书的实验不同，这套**不需要 GPU 和模型权重**，Python 3.10+ 标准库即可）：

```bash
git clone https://github.com/bojieli/ai-infra-book.git
cd ai-infra-book

# 查看支持的模型
python3 calculations/calc.py models

# 估算 Qwen3-8B 在 8192-token prefill 下的逐算子资源需求
python3 calculations/calc.py forward --model qwen3-8b --tokens 8192 --format md
```

仓库用 Git LFS 存论文与测量记录（约 20 GB），`.lfsconfig` 默认跳过全部 LFS 文件：克隆后正文与静态计算即可用，复现某个实验时再 `git lfs pull --include="experiments/chXX/..."` 拉对应目录。

## 四、怎么读

**最省力的路径**（作者在 README 给了按角色的建议，这里是压缩版）：

1. **第 1–3 章**先建框架：模型架构与负载特性，全书的地基
2. 按方向选重点：
   - 应用 / 推理服务 → **第 8、9 章**，再看 11、12；遇到容量、算子、通信问题时回到 4–7 追因
   - 系统 / 网络 → **第 5–7 章**，再看 9、10
   - 芯片 / 体系结构 → **第 4–7 章**，用后续章节的任务算例检验硬件指标如何转化为服务能力
3. **遇到算例先自己估，再看推导和实验**——这是「从约束推导设计」的练法；用 `calculations/calc.py` 换成自己在用的模型和硬件复算，看结论是否改变

**与本库排程的关系**：AI 线当前固定投入是理论 + 工程两线每周同步、实操线每周 2–3h；这本**不新开周程**，定位是 Agent 实操线与工程地图 L3 层遇到性能 / 成本问题时回查的系统层参考。考研数学主线不受影响（前置只要线性代数）。
