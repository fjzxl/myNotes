# Agent 实操线：《深入理解 AI Agent》109 实验执行计划

> 把 [深入理解 AI Agent](understanding-ai-agent.md)（李博杰，Apache-2.0，本地 PDF）从「原理层笔记」变成可执行的练习线。
> **时间预算**：每周 2-3h（或隔周一次 3h 的完整 session），与理论线（[ml-booklist](ml-booklist.md) 的 5-6h/周）**分开记账、互不挤占**；服务对象是求职作品线与工程直觉，不是考研。
> **核心方法**（作者原话的精神）：读懂设计原则后**用 coding agent 从头实现一遍**，观察输出、排查不符合预期——不是逐行读配套代码。

---

## 一、贯穿项目与总原则

整条线围绕一个贯穿项目：**做一个自己的小型 coding agent，逐阶段把它养大**。每阶段的实验都是往这个项目里加一块能力，最终它就是求职作品集的主仓库。

三条总原则，全部来自 [Claude Code](Claude%20Code.md) 心得，在实操线里逐条落实：

1. **每个实验有机器可验证的完成信号**——跑通输出、测试通过、diff 可审，不靠「看起来对」；
2. **任务书先行**——动手前写清背景/范围/验收/排除项，练习「描述问题的能力」本身就是本线的核心训练；
3. **危险操作人工确认**——凡是会删文件、写外部服务的实验，验收里必须含人工检查步骤。

## 二、五个阶段

按作者推荐的阅读顺序（1 → 2+4 → 3+5 → 7+9 → 按需）组织，每阶段给出实验量、产出物与对接点：

| 阶段 | 章 · 实验量 | 核心练习 | 产出物 | 对接 |
|---|---|---|---|---|
| **A · 起步** | Ch1（4）+ Ch2 上下文工程（10） | 环境（uv + Python 3.11-3.13）；跑通最小 Agent；挑上下文工程实验（提示、压缩、Agent Skills 各选代表） | 可运行的最小 Agent + 一份自己的「上下文工程 checklist」 | [AI Engineering 导读](ai-engineering.md) p.146-175（Context Engineering 章） |
| **B · 工具与记忆** | Ch4 工具/MCP（5）+ Ch3 记忆知识库（12） | 给 Agent 接 MCP 工具（感知/执行/协作各一类）；加跨会话用户记忆与一个小 RAG | 带 MCP 工具 + 记忆的 Agent | AE p.264-303（MCP 章）；MoE 篇的「分布式视角」作拓展对照 |
| **C · Coding Agent** | Ch5（16） | 生产级 Coding Agent 架构；用**主控-执行拓扑**把项目重构成 orchestrator + worker | **求职主作品：一个小而完整的 coding agent**（README + 任务书样例 + 演示） | Claude Code 篇全部三件高级事；理论线 W11-W13 同步读 AE p.176-254 |

节奏参考（每周 2-3h）：A 约 4 周、B 约 4 周、C 约 6 周、D 约 4 周——A-D 合计约 18 周，与理论线的阶段二大体同期；E 开放，做完 D 再说。

## 三、拓扑练习：把 Claude Code 篇的四种拓扑逐一用上

[Claude Code](Claude%20Code.md) 篇总结的四种多智能体拓扑，在本线里各有一次实操场：

- **主控-执行**：阶段 C——orchestrator 拆解任务、worker 各领一个子任务，正好是第 5 章 Coding Agent 架构的骨架；
- **串行流水线**：阶段 C/D 之间——「先设计方案 → 再实现 → 再评审」三段式，每段一个 agent 角色；
- **生成-评审**：阶段 D——一个 agent 写实现，一个只对着验收标准挑毛病，把评审也变成实验；
- **并行扇出**：阶段 E——多个 agent 独立调研同一问题（如「三种记忆方案的取舍」），汇总结论。

每用一种拓扑，回 Claude Code 篇的实践清单打一次勾——那条清单就是本线的纠偏器。

## 四、与理论线 / 求职线的关系

- **不等理论线**：实操线现在就能开始（前置只是 Python + LLM 产品使用经验，全书除第 8 章外对数学要求很低）；理论线 W11-W13 读 AE Agents 段（p.176-254）时，阶段 C 恰好提供工程侧的对照——两边互证，不互相等待。
- **错峰规则**：考研冲刺期（考前 2-3 个月）实操线冻结，只保留「跑通即止」的维护性操作；与理论线同一条纪律。
- **求职作品**：阶段 C/D 的产出按作品集标准做——公开仓库、可复现的 README、一段演示、一份评估报告。FDE 篇（[fde-guide](fde-guide.md)）的「交付旅程」叙事可以直接套用在 README 里：解决正确的问题 → 激活部署 → 守住质量。

- 环境：Python 3.11-3.13，`uv` 管理依赖（书的标准配置）；
