# 一、语言基础

> 📚 本文是 [[topics/programming/Web/javascript|JavaScript 核心知识体系]] 的第 1 / 8 章。 下一章：[[topics/programming/Web/javascript/02-reference-types|二、引用类型详解]]


> **本章定位：** JavaScript 学习的起点。我们将从最基本的"砖块"开始：数据类型是什么、变量如何声明、运算符如何工作。不要小看这些基础——JavaScript 中几乎所有复杂的特性（闭包、原型链、异步）都建立在这些基础概念之上。
>
> **学习路线：** 数据类型（是什么）→ 变量与作用域（怎么存）→ 运算符（怎么算）→ 实操练习
>
> **建议：** 每读完一个小节，就在浏览器控制台（F12 → Console）里亲手敲一遍示例代码。基础概念不需要死记硬背，多敲几遍自然就记住了。

### 1.1 数据类型
#### 基本类型（string / number / boolean / null / undefined / symbol / bigint）

**一句话理解：** 基本类型就像你手里的现金——面值是固定的，给别人的时候是复制一份给对方，你手里的那份不会变。

**生活类比：**
- 基本类型 = **复印件**：你把身份证复印件给别人，别人怎么涂改他的复印件，都不会影响你手里原件的内容
- 引用类型 = **共享文档链接**：你把云文档链接发给同事，你们看到的是同一份文档，任何一方修改，另一方都会看到变化

**内存模型图解：**

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          基本类型：值传递                                   │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   let a = 'hello';         let b = a;          b = 'world';               │
│   ┌─────────┐              ┌─────────┐          ┌─────────┐               │
│   │  变量   │              │  变量   │          │  变量   │               │
│   │   a     │              │   b     │          │   b     │               │
│   ├─────────┤              ├─────────┤          ├─────────┤               │
│   │ 'hello' │              │ 'hello' │          │ 'world' │               │
│   └─────────┘              └─────────┘          └─────────┘               │
│       │                        │                    │                      │
│       ▼                        ▼                    ▼                      │
│   ┌─────────────────────────────────────────────────────────────┐           │
│   │                      栈内存（Stack）                         │           │
│   │         每个变量有独立的空间，赋值时复制整个值                  │           │
│   └─────────────────────────────────────────────────────────────┘           │
│                                                                             │
│   结论：a 和 b 是完全独立的两份数据，互不影响                                │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│                          引用类型：引用传递                                 │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   let obj1 = {name: 'Alice'};    let obj2 = obj1;      obj2.name = 'Bob'  │
│   ┌─────────┐                     ┌─────────┐            ┌─────────┐      │
│   │  obj1   │────────────────────▶│  obj2   │            │  obj2   │      │
│   ├─────────┤                     ├─────────┤            ├─────────┤      │
│   │ 地址 #A  │                     │ 地址 #A  │            │ 地址 #A  │      │
│   └────┬────┘                     └────┬────┘            └────┬────┘      │
│        │                               │                       │          │
│        │      堆内存（Heap）            │                       │          │
│        ▼                               ▼                       ▼          │
│   ┌─────────────┐              ┌─────────────┐         ┌─────────────┐   │
│   │   #A        │◀─────────────│   #A        │◀────────│   #A        │   │
│   │ {name:      │              │ (同一个对象) │         │ {name:      │   │
│   │  'Alice'}   │              │             │         │  'Bob'}     │   │
│   └─────────────┘              └─────────────┘         └─────────────┘   │
│                                                                             │
│   结论：obj1 和 obj2 指向同一个对象，修改互相影响                            │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

JavaScript 共有 7 种基本数据类型，其共同特征是**不可变（immutable）**且按**值传递**：

| 类型 | 说明 | 示例 |
|------|------|------|
| `string` | 字符串，单双引号及反引号均可 | `'hello'` |
| `number` | 整数与浮点数统一为 number | `42`, `3.14`, `NaN`, `Infinity` |
| `boolean` | 布尔值 | `true`, `false` |
| `null` | 表示空值（历史遗留 bug：`typeof null === 'object'`） | `null` |
| `undefined` | 未定义 | `undefined` |
| `symbol` | ES6 引入的唯一标识符 | `Symbol('desc')` |
| `bigint` | ES2020 引入的任意精度整数 | `9007199254740991n` |

- 基本类型赋值时复制值本身（按值传递），现代引擎可能将部分基本类型值存储在堆中（如大字符串、HeapNumber），但语义上仍是值复制
- `typeof` 对基本类型的返回值：`"string"`, `"number"`, `"boolean"`, `"undefined"`, `"symbol"`, `"bigint"`, `"object"` (null)

```js
// 基本类型的值传递：修改副本不影响原件
let a = 'hello';
let b = a;      // b 得到了 'hello' 的副本
b = 'world';    // 修改 b
console.log(a); // "hello" —— a 不受影响

// typeof 检测
console.log(typeof 'hi');      // "string"
console.log(typeof 42);        // "number"
console.log(typeof true);      // "boolean"
console.log(typeof undefined); // "undefined"
console.log(typeof Symbol());  // "symbol"
console.log(typeof 123n);      // "bigint"
console.log(typeof null);      // "object" ← 历史 bug，记住它！

// 特殊 number 值
console.log(typeof NaN);       // "number"
console.log(typeof Infinity);  // "number"
console.log(0.1 + 0.2);        // 0.30000000000000004（浮点数精度问题）
```


**初学者常见错误：**
- ❌ `typeof null === 'object'` 是 JavaScript 的历史 bug，判断 null 应使用 `value === null`
- ❌ `0.1 + 0.2 !== 0.3`，浮点数运算有精度问题，比较时应使用容差：`Math.abs(a - b) < Number.EPSILON`
- ❌ `NaN === NaN` 为 `false`，判断 NaN 应使用 `Number.isNaN()`
- ❌ `Symbol()` 每次调用都创建新的唯一值，`Symbol('a') === Symbol('a')` 为 `false`

#### 引用类型（object / array / function）


**内存结构对比：**

```
栈内存 (Stack)                           堆内存 (Heap)
┌─────────────────────┐             ┌─────────────────────┐
│ a: "hello"          │             │  {name: "A"}        │ ◄── 地址 0x1001
│ b: "hello"  (副本)   │             │                     │
│                     │             │  {name: "B"}        │ ◄── 地址 0x1002
│ obj1: 0x1001 ───────┼────────────►│                     │
│ obj2: 0x1001 ───────┼────────────►│                     │
│       ↑             │             │    （共享引用）      │
│       └─────────────┘             └─────────────────────┘
│
│   基本类型：变量直接存值（独立副本）
│   引用类型：变量存地址，多个变量可指向同一对象
└─────────────────────────────────────────────────────────
```


**一句话理解：** 引用类型的变量保存的不是数据本身，而是数据在内存中的"门牌号"。多个变量可以持有同一个门牌号，所以修改数据时所有人都能看到变化。

**生活类比：**
- 引用类型 = **房屋租赁合同上的地址**：合同上写的是"xx小区3栋501"，你和室友手里各有一份合同（引用），但你们住的是同一套房子（内存中的对象）。室友把沙发搬走了，你回家也会发现沙发没了。
- 基本类型 vs 引用类型的赋值差异：
  ```js
  // 基本类型：复制的是值本身（两份独立的数据）
  let a = 100;
  let b = a;      // b 得到了 100 的复印件
  b = 200;        // 修改 b，a 不受影响
  console.log(a); // 100

  // 引用类型：复制的是引用地址（指向同一份数据）
  let obj1 = { name: 'Alice' };
  let obj2 = obj1;   // obj2 得到了同一把钥匙
  obj2.name = 'Bob'; // 通过 obj2 修改了房子里的东西
  console.log(obj1.name); // "Bob" —— obj1 也看到了变化
  ```

引用类型的值存储在**堆内存**中，变量保存的是指向堆内存的**引用地址**。赋值时复制的是引用地址（按值传递引用，即 pass-by-sharing），而非对象本身：

| 类型 | 说明 |
|------|------|
| `object` | 键值对集合 |
| `array` | 有序集合（本质是特殊对象） |
| `function` | 可调用对象（`typeof fn === 'function'`） |
| `date`, `regExp`, `map`, `set` 等 | 内置对象 |

- 两个对象即使内容相同，引用不同也不相等：`{} === {} // false`
- 修改引用类型的属性会影响所有持有该引用的变量


**初学者常见错误：**
- ❌ 以为 `const obj = {}` 后 `obj = {}` 可以执行——`const` 禁止重新赋值引用，但可以修改对象属性
- ❌ 用 `===` 比较两个内容相同的对象：`{a: 1} === {a: 1}` 为 `false`，因为比较的是引用地址
- ❌ 函数参数传递时修改对象，期望不影响原对象——引用类型参数是共享引用，修改会影响外部
- ✅ 需要复制对象时，使用展开运算符 `{...obj}`（浅拷贝）或 `structuredClone(obj)`（深拷贝）

#### 类型检测与转换

**一句话理解：** JavaScript 是弱类型语言，变量没有固定类型，运行时引擎会自动或手动地在不同类型之间转换。

**类型检测方法：**

| 方法 | 适用场景 | 示例 |
|------|----------|------|
| `typeof` | 基本类型（除 null）、function | `typeof 'a' // 'string'` |
| `instanceof` | 引用类型的原型链判断 | `arr instanceof Array` |
| `Object.prototype.toString.call()` | 最可靠的通用类型判断 | `[object Object]`, `[object Array]` |

**类型转换规则（重点掌握）：**

```js
// 隐式转换触发场景
'5' + 3      // '53'（字符串拼接）
'5' - 3      // 2（数字运算）
!0           // true（转布尔）
if ('') {}   // false（空字符串转布尔为 false）

// 显式转换
Number('123')    // 123
String(123)      // '123'
Boolean(1)       // true
parseInt('10px') // 10
```

**初学者常见错误：**
- ❌ 用 `==` 做比较，导致意外的类型转换：`0 == ''` 为 `true`，`'0' == false` 为 `true`
- ✅ 始终使用 `===` 和 `!==` 进行比较，避免隐式转换带来的 bug
- ❌ `typeof null === 'object'` 是 JavaScript 的历史 bug，判断 null 应直接用 `value === null`
- ❌ `typeof [] === 'object'`，数组判断应使用 `Array.isArray(arr)`

- **falsy 值**：`0`, `0n`, `""`, `null`, `undefined`, `NaN`, `false`（在布尔上下文都转为 `false`）
- 优先使用 `===` 和 `!==` 避免隐式转换带来的意外行为


### 1.2 变量与作用域
#### 声明方式（var / let / const）

**一句话理解：** `var` 是"老年代的变量声明"（函数作用域、可重复声明、有变量提升），`let` 和 `const` 是 ES6 引入的"现代声明方式"（块级作用域、不可重复声明、无变量提升）。

**生活类比：**
- `var` = **全村广播的大喇叭**：声音（变量）能传遍整个村子（函数），而且你可以反复喊同一个名字，后面的会覆盖前面的
- `let` = **房间内的对讲机**：声音只在当前房间（块级 `{}`）内有效，不同房间可以喊相同的名字互不干扰
- `const` = **房间内的对讲机 + 封条**：一旦贴上封条（赋值），就不能再更改内容（但如果是引用类型，封条封的是"门牌号"，房子里的东西还是可以动的）

| 特性 | `var` | `let` | `const` |
|------|-------|-------|---------|
| 作用域 | 函数作用域 | 块级作用域 | 块级作用域 |
| 重复声明 | 允许 | 不允许 | 不允许 |
| 变量提升 | 提升并初始化为 `undefined` | 提升但处于 TDZ | 提升但处于 TDZ |
| 重新赋值 | 可以 | 可以 | 不可以（但对象/数组内容可变） |
| 声明时初始化 | 不必 | 不必 | 必须 |

**变量提升图解：**

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           变量提升（Hoisting）                             │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   【var 的提升】                                                           │
│                                                                             │
│   写出来的代码：                        引擎实际理解成：                     │
│   ──────────────────                   ──────────────────────               │
│                                                                             │
│   console.log(a);                    var a;         ← 声明被提升           │
│   var a = 1;                        console.log(a);  ← 此时 a 是 undefined  │
│                                        a = 1;         ← 赋值留在原地        │
│                                                                             │
│   输出：undefined                       输出：undefined                       │
│                                                                             │
│   💡 记忆口诀：var 变量提升，声明像"浮"到顶部，赋值还"沉"在原地            │
│                                                                             │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   【let/const 的提升——暂时性死区（TDZ）】                                   │
│                                                                             │
│   写出来的代码：                        引擎实际理解成：                     │
│   ──────────────────                   ──────────────────────               │
│                                                                             │
│   console.log(b);  ← 报错 ReferenceError     let b = 2;                      │
│   let b = 2;                           ↑ TDZ 在初始化完成后才结束            │
│                                                                             │
│   输出：ReferenceError                  输出：ReferenceError                  │
│                                                                             │
│   ⚠️ 重要：TDZ 期间变量存在但不可访问，就像快递到了驿站但还没收到取件码     │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

```js
// var 的变量提升
console.log(a); // undefined（不会报错）
var a = 1;

// let 的暂时性死区
console.log(b); // ReferenceError: Cannot access 'b' before initialization
let b = 2;

// const 对象属性可变
const obj = { x: 1 };
obj.x = 2;      // 合法
obj = {};       // TypeError: Assignment to constant variable
```

**🔺 重点：最佳实践**

```js
// 1. 默认使用 const
const PI = 3.14159;
const config = { theme: 'dark' };

// 2. 需要重新赋值时使用 let
let count = 0;
count++;

// 3. 循环中必须用 let（var 会导致闭包问题）
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100); // 输出 0, 1, 2 ✅
}

// 如果用 var：
for (var j = 0; j < 3; j++) {
  setTimeout(() => console.log(j), 100); // 输出 3, 3, 3 ❌
}
```

**最佳实践：**
1. 默认使用 `const`，需要重新赋值时改用 `let`
2. 彻底避免使用 `var`
3. 在循环体中使用 `let` 创建块级绑定，避免闭包共享问题


**初学者常见错误：**
- ❌ 在循环中使用 `var` 声明计数器，导致所有回调共享同一个变量：`for (var i = 0; i < 3; i++) { setTimeout(() => console.log(i), 0); }` 输出 3 个 3
- ✅ 循环中声明计数器应使用 `let`，每次迭代都有独立的绑定
- ❌ `const arr = []; arr.push(1);` 是可以的——`const` 只保证引用不变，不保证内容不变
- ❌ 声明前访问 `let`/`const` 变量会报 `ReferenceError`（TDZ），而不是返回 `undefined`

#### 作用域链与词法作用域

**一句话理解：** 作用域就是变量的"活动范围"，词法作用域意味着这个范围在代码写下来的时候就确定了，不会因为调用位置不同而改变。

**生活类比：**
- 作用域 = **俄罗斯套娃**：外层套娃看不到内层套娃里的小纸条（变量），但内层套娃可以翻看外层套娃里的所有纸条
- 词法作用域 = **身份证上的籍贯**：你的籍贯在出生时（代码编写时）就确定了，不会因为后来搬到北京工作（运行时调用）就变成北京人

**作用域类型：**
- **全局作用域**：最外层，所有代码共享
- **函数作用域**：`function` 内部
- **块级作用域**：`{}` 内部（`let`/`const`/`class`）

**词法作用域（Lexical Scoping）：**

词法作用域也叫"词法作用域（静态作用域）"，核心规则只有一条：**函数能访问哪些变量，由它在哪里"定义"决定，而不是在哪里"调用"决定。**

```js
const name = '全局';

function foo() {
  console.log(name); // foo 定义在全局，所以这里的 name 就是全局的 name
}

function bar() {
  const name = 'bar内部';
  foo(); // ❗️ 在 bar 内部调用 foo，但 foo 并不会因此访问到 bar 里的 name
}

bar(); // 输出："全局"  （不是 "bar内部"）
```

**关键理解**：无论 `foo()` 在哪里被调用（全局、bar 内部、甚至另一个文件），它内部的 `name` 始终指向**定义时**所在作用域的那个变量。这就是"词法"的含义——作用域在代码**写出来**（词法分析阶段）就固定了，跟运行时怎么调用没关系。

**对比：如果是动态作用域（JavaScript 不是，但有助于理解）**

```js
// 假设 JS 是动态作用域（实际不是）
function bar() {
  const name = 'bar内部';
  foo(); // 动态作用域下，foo 会访问到 bar 内部的 name
}
bar(); // 假设输出："bar内部"
```

> 有些语言（如 Bash 的局部变量）使用动态作用域，但 JavaScript、C、Java 等主流语言都采用词法作用域。

**嵌套作用域的访问规则：**

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           作用域嵌套与作用域链                             │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   const global = 'global';                                                 │
│   function outer() {                                                       │
│     const outerVar = 'outer';                                              │
│     function inner() {                                                     │
│       const innerVar = 'inner';                                            │
│       // inner 可以向上访问 outer 和 global                                 │
│       console.log(global, outerVar, innerVar); // 均可访问 ✅               │
│     }                                                                      │
│     inner();                                                               │
│     // outer 不能向下访问 inner 的变量                                      │
│     // console.log(innerVar); // ReferenceError ❌                         │
│   }                                                                        │
│   outer();                                                                 │
│                                                                             │
│   ┌─────────────────────────────────────────────────────────────────┐     │
│   │                        作用域链示意图                             │     │
│   └─────────────────────────────────────────────────────────────────┘     │
│                                                                             │
│         ┌─────────────────────────────────────┐                           │
│         │          全局作用域                  │  ← 作用域链顶端         │
│   ─────▶│  global = 'global'                  │                        │
│         │  outer = <function>                  │                        │
│         └──────────────────┬──────────────────┘                           │
│                            │                                               │
│                            ▼ [找到 outerVar]                              │
│         ┌─────────────────────────────────────┐                           │
│         │          outer 函数作用域             │                           │
│   ─────▶│  outerVar = 'outer'                  │                        │
│         │  inner = <function>                  │                        │
│         └──────────────────┬──────────────────┘                           │
│                            │                                               │
│                            ▼ [找到 innerVar]                              │
│         ┌─────────────────────────────────────┐                           │
│         │          inner 函数作用域             │  ← 当前查找起点         │
│         │  innerVar = 'inner'                  │                        │
│         └─────────────────────────────────────┘                           │
│                                                                             │
│   查找规则：从当前作用域开始，逐层向上查找，找到就停止                       │
│             找不到就报 ReferenceError                                      │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

```js
const global = 'global';
function outer() {
  const outerVar = 'outer';
  function inner() {
    const innerVar = 'inner';
    // inner 可以向上访问 outer 和 global
    console.log(global, outerVar, innerVar); // 均可访问
  }
  inner();
  // outer 不能向下访问 inner 的变量
  // console.log(innerVar); // ReferenceError
}
outer();
```

- **🔺 由内向外**：子作用域可以访问父作用域的变量
- **⚠️ 由外向内**：父作用域无法访问子作用域的变量
- **⚠️ 同级之间**：兄弟作用域互相隔离，无法访问彼此的变量

**作用域链：** 当查找变量时，引擎从当前作用域开始，逐层向外（上级词法环境）查找，直到全局作用域，仍未找到则抛出 `ReferenceError`。

**📝 记忆口诀：** 作用域查找像"查户口"，内层可以看外层，外层看不见内层，同层之间不相往来。

#### 暂时性死区（TDZ）

**一句话理解：** `let` 和 `const` 声明的变量虽然被"提升"了（引擎知道它存在），但在正式声明之前，你既不能读也不能写，否则会报错。这个"既不能碰也不能看"的时间段就是暂时性死区。

**生活类比：**
- TDZ = **快递已到驿站但还没收到取件码**：包裹（变量）确实已经在驿站（作用域）里了，但你没有取件码（声明语句），所以既不能打开也不能带走，强行拿会被报警（ReferenceError）
- 相比之下，`var` 的变量提升就像**驿站自动帮你签收并把包裹放在门口**：你可以在收到通知前就拿走（虽然值是 `undefined`）

Temporal Dead Zone：从块级作用域起始位置到变量声明语句之间的区域。

```js
{
  // TDZ 开始
  console.log(value); // ReferenceError
  // TDZ 结束
  let value = 42;
}
```

- TDZ 内访问变量会抛出 `ReferenceError`，而非 `undefined`
- 即使外部存在同名变量，TDZ 期间也不会访问到外部作用域
- `typeof` 在 TDZ 内同样会报错（这是 `let`/`const` 与 `var` 的重要区别）


### 1.3 运算符与表达式
#### 算术 / 比较 / 逻辑运算符

**一句话理解：** 运算符是 JavaScript 进行数学计算、条件判断和逻辑组合的基本工具，掌握它们的优先级和特殊性是写出正确表达式的前提。

**算术运算符：** `+`, `-`, `*`, `/`, `%`, `**`, `++`, `--`

```js
// 特殊行为
'5' + 3      // '53'（+ 号一侧为字符串时转为拼接）
'5' - 3      // 2（其他算术运算强制转数字）
NaN + 1      // NaN（传染性）
0.1 + 0.2    // 0.30000000000000004（浮点精度问题）
```

**比较运算符：**

| 运算符 | 说明 |
|--------|------|
| `==` | 相等（发生隐式类型转换） |
| `===` | 严格相等（类型和值都相同） |
| `!=` / `!==` | 不等 / 严格不等 |
| `>`, `<`, `>=`, `<=` | 大小比较 |

**== vs === 对比图：**

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           == vs ===  对比                                 │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   === 严格相等                    == 相等（会转换类型）                      │
│   ──────────────────             ────────────────────────────              │
│   类型必须相同                    类型可以不同，会自动转换                   │
│   值必须相同                      值需要"相等"（转换后）                     │
│                                                                             │
│   例子：                        例子：                                      │
│   5 === 5        → true         5 == 5         → true                    │
│   5 === '5'      → false       5 == '5'       → true （字符串转数字）     │
│   true === 1     → false       true == 1       → true （布尔转数字）       │
│   null === undefined → false   null == undefined → true （规范规定）        │
│                                                                             │
│   ⚠️ 极端案例：                                                          │
│   [] == ![]       → true                                                │
│   解释：![] → false；然后 [] == false，false 转数字 0；                    │
│         [] 转原始值 ''，'' 转数字 0；最终 0 == 0 → true                      │
│                                                                             │
│   💡 记忆口诀：                                                         │
│   「用 ===，类型值都要查；用 ==，偷偷转换易出锅」                          │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

```js
null == undefined;     // true（规范规定）
null === undefined;    // false
0 == '0';              // true
0 === '0';             // false
[] == ![];             // true（隐式转换的极端案例）
```

> **💡 原则**：始终使用 `===` 和 `!==`，除非明确需要隐式转换。面试答错这题，HR 直接 pass！

**逻辑运算符：** `&&`（与）、`||`（或）、`!`（非）


**初学者常见错误：**
- ❌ 用 `==` 做比较导致意外类型转换：`0 == ''` 为 `true`，`'0' == false` 为 `true`，`null == undefined` 为 `true`
- ✅ 始终使用 `===` 和 `!==` 进行严格相等比较，避免隐式转换的坑
- ❌ 逻辑运算符返回的不一定是布尔值：`'' || 'default'` 返回 `'default'`，`0 && 'ok'` 返回 `0`
- ❌ 加法运算符的隐式转换：`'5' + 3` 得到 `'53'`（字符串拼接），`'5' - 3` 得到 `2`（数字运算）

#### 短路求值与空值合并（??）

**一句话理解：** 短路求值让逻辑运算在确定结果时提前停止，空值合并运算符 `??` 则提供了一种只针对 `null` 和 `undefined` 设置默认值的安全方式。

逻辑运算符的返回值不总是布尔值，而是**决定结果的那个操作数**：

```js
// &&：左侧 falsy 则返回左侧，否则返回右侧
0 && 'hello'          // 0
'world' && 'hello'    // 'hello'

// ||：左侧 truthy 则返回左侧，否则返回右侧
0 || 'default'        // 'default'
'' || 'fallback'      // 'fallback'
```

**空值合并运算符 `??`**（ES2020）：
- 仅在左侧为 `null` 或 `undefined` 时返回右侧，否则返回左侧
- 与 `||` 的核心区别：`||` 将所有 falsy 值（`0`、`0n`、`''`、`false`、`NaN`、`null`、`undefined`）视为"假"，而 `??` 只识别 `null` 和 `undefined`

**|| vs ?? 对比图：**

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           || vs ??  对比                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   || 或运算符                        ?? 空值合并运算符                       │
│   ─────────────────                 ───────────────────────                 │
│   左侧为 falsy 时返回右侧            左侧为 null/undefined 时返回右侧        │
│                                                                             │
│   Falsy 值包括：                    只认为"空"的值：                        │
│   0, '', false, NaN,               null, undefined                         │
│   null, undefined                                                     │
│                                                                             │
│   ┌─────────────────────────────────────────────────────────────────┐    │
│   │  const count = 0;                                               │    │
│   │  count || 10   →  10    （0 是 falsy，所以用右侧的 10）         │    │
│   │  count ?? 10   →  0     （0 不是 null/undefined，保留左侧）      │    │
│   │                                                                  │    │
│   │  const name = '';                                               │    │
│   │  name || 'Anonymous'  →  'Anonymous' （'' 是 falsy）           │    │
│   │  name ?? 'Anonymous'  →  ''          （'' 不是 null/undefined）│    │
│   │                                                                  │    │
│   │  const age = null;                                              │    │
│   │  age || 18     →  18    （null 是 falsy，也是 null/undefined）  │    │
│   │  age ?? 18     →  18    （null 是 null/undefined）              │    │
│   └─────────────────────────────────────────────────────────────────┘    │
│                                                                             │
│   ⚠️ 什么时候用 ??：当你需要区分"没有值"和"值是 0/空字符串/false"时    │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

```js
const count = 0;
count || 10;     // 10（`||` 认为 0 是假值，返回右侧）
count ?? 10;     // 0（`??` 认为 0 是有效值，返回左侧）

const name = '';
name || 'Anonymous';  // 'Anonymous'（意外！）
name ?? 'Anonymous';  // ''（正确，空字符串是有效值）
```

> **⚠️ 语法注意**：`??` 不能与 `||` 或 `&&` 混用而不加括号，会报语法错误。
> ```js
> // ❌ 语法错误
> a ?? b || c
>
> // ✅ 需要加括号
> a ?? (b || c)
> ```


**初学者常见错误：**
- ❌ 混淆 `||` 和 `??`：`0 || 'default'` 返回 `'default'`（因为 0 是 falsy），但 `0 ?? 'default'` 返回 `0`（因为 0 不是 null/undefined）
- ✅ `??` 只在左侧为 `null` 或 `undefined` 时才返回右侧值，适合设置默认值
- ❌ `&&` 的短路求值被误用：`obj && obj.name` 在 `obj` 为 falsy 时返回 `obj` 本身，不是 `false`

#### 可选链（?.）

**一句话理解：** 可选链运算符 `?.` 让你在访问嵌套对象属性时，如果中间某一层是 `null` 或 `undefined`，不会报错，而是直接返回 `undefined`。

ES2020 引入，安全访问嵌套属性，避免深层空值检查：

```js
const user = { profile: null };

// 传统写法
const name = user && user.profile && user.profile.name;

// 可选链
const nick = user?.profile?.name;  // undefined（不报错）

// 其他用法
user?.getName?.();                 // 安全调用函数
arr?.[0];                          // 安全访问数组
```

- 短路行为：遇到 `null`/`undefined` 立即停止，返回 `undefined`
- **不能用于赋值左侧**：`user?.name = 'Tom' // SyntaxError`
- 与 `??` 组合使用是最佳实践：`const name = user?.name ?? 'Anonymous'`



**初学者常见错误：**
- ❌ 试图用可选链赋值：`obj?.name = 'Alice'` 会报错，可选链只能用于读取，不能用于赋值
- ❌ 以为 `obj?.name?.first` 返回 `undefined` 后还能继续 `.toUpperCase()` —— 需要配合 `??` 提供默认值
- ✅ 正确使用：`const firstName = user?.profile?.name ?? 'Anonymous';`
- ❌ 滥用可选链掩盖了本不该为空的逻辑错误——可选链是"容错"不是"遮羞布"

### 🛠️ 实操：语言基础巩固

#### 实现一个类型判断工具函数（兼容基本类型与引用类型）

**核心思路：** `typeof` 对基本类型友好但对引用类型无能为力（`typeof [] === 'object'`），而 `Object.prototype.toString.call()` 可以返回精确的内部类型标签 `[object Array]`、`[object Null]` 等。

**实现要点：**
- 使用 `Object.prototype.toString.call(value)` 获取内部类型标签
- 提取标签中的类型名（`[object Xxx]` → `xxx`）
- 统一转为小写，返回标准化类型字符串

**关键细节：**
- `typeof null === 'object'` 是历史 bug，`getType(null)` 应返回 `'null'`
- `typeof [] === 'object'`，`typeof /abc/ === 'object'`，需要更精确的判断方法

```js
function getType(value) {
  const type = Object.prototype.toString.call(value);
  // 提取 "[object Xxx]" 中的 Xxx
  return type.slice(8, -1).toLowerCase();
}

// 验证
console.log(getType('hello'));      // 'string'
console.log(getType(123));          // 'number'
console.log(getType(true));         // 'boolean'
console.log(getType(null));         // 'null'
console.log(getType(undefined));    // 'undefined'
console.log(getType([]));           // 'array'
console.log(getType({}));           // 'object'
console.log(getType(() => {}));     // 'function'
console.log(getType(/abc/));        // 'regexp'
console.log(getType(new Date()));   // 'date'
console.log(getType(Symbol()));     // 'symbol'
console.log(getType(123n));         // 'bigint'
```

#### 用 var / let / const 分别编写作用域差异对比示例

**1. 重复声明差异**

```js
// var 允许重复声明，后面的覆盖前面的
var x = 1;
var x = 2;
console.log(x); // 2（不会报错）

// let 和 const 不允许重复声明
let y = 1;
// let y = 2;   // ❌ SyntaxError: Identifier 'y' has already been declared

const z = 1;
// const z = 2; // ❌ SyntaxError: Identifier 'z' has already been declared
```

**2. 变量提升行为差异**

```js
// var：声明提升，初始化值为 undefined
console.log(a); // undefined（不会报错）
var a = 1;
// 实际执行顺序：var a; console.log(a); a = 1;

// let：声明提升，但处于 TDZ，访问报错
console.log(b); // ReferenceError: Cannot access 'b' before initialization
let b = 2;

// const：与 let 相同
console.log(c); // ReferenceError: Cannot access 'c' before initialization
const c = 3;
```

**3. 循环中闭包的绑定差异（经典面试题）**

```js
// ❌ var：循环变量共享同一个绑定，最终都输出 3
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// 输出：3, 3, 3

// ✅ let：每次迭代创建新的块级绑定，输出 0, 1, 2
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// 输出：0, 1, 2

// var 的修复方案：利用 IIFE 创建独立作用域
for (var i = 0; i < 3; i++) {
  (function(j) {
    setTimeout(() => console.log(j), 100);
  })(i);
}
// 输出：0, 1, 2
```

> 💡 **为什么是 3, 3, 3？** `var` 的循环变量在函数作用域中只有一个，所有 `setTimeout` 回调共享同一个 `i`；等它们执行时，循环早已结束，`i` 变成了 3。而 `let` 每次迭代都会创建一个新的块级绑定。背后的原理涉及**作用域链**和**闭包**，详见第 3 章「词法作用域与闭包」。

**核心结论速查表**

| 场景 | `var` | `let` | `const` |
|------|-------|-------|---------|
| 重复声明 | ✅ 允许 | ❌ 报错 | ❌ 报错 |
| 声明前访问 | `undefined` | `ReferenceError` | `ReferenceError` |
| 循环闭包 | 共享绑定 | 独立绑定 | for...of/in 可用 |
| 块级作用域 | ❌ 函数级 | ✅ 块级 | ✅ 块级 |
